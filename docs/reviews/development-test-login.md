# Automatic local test sign-in

The founder requested sign-in without typing the saved synthetic account details. Visiting `/sign-in` in opted-in local development attempts that account once after hydration. Automatic mode shows a signing-in status instead of empty credential fields and offers a retry if the provider is unavailable. “Use another account” opens `/sign-in?manual=1`, where normal email/password entry remains available. Explicit sign-out also returns to that manual URL, suppressing the automatic attempt. Reactive search parameters let navigation from manual to automatic mode start a new attempt without remounting the page; repeated renders do not duplicate it.

`TALKINGSTAGE_DEV_TEST_LOGIN=1` is enabled in the ignored local environment. The example environment defaults to zero. The server-only loader reads the existing private hosted-test JSON only for development requests on a loopback host and configured local port. The action additionally requires a matching Origin, verifies the saved fixture belongs to the configured backend and fixed synthetic email, and passes its credentials through the ordinary sign-in flow. An existing signed-in account is preserved. Passwords are not returned as props, placed in form fields, included in client-side code or stored in browser local storage. Production, public hosts, mismatched origins/projects and missing or malformed fixtures fail closed.

Normal authentication, adult declaration and onboarding checks remain in force. Supabase session cookies retain the existing HttpOnly and SameSite protections. The effect and in-flight guards prevent duplicate automatic attempts; errors do not trigger an automatic retry loop. Regular auth/hosted test configurations explicitly disable the shortcut to avoid accidental account substitution.

Validation: the dedicated browser test passed against the existing hosted synthetic account with AI disabled. It checked the manual opt-out, a single automatic sign-in, arrival at Discover, credentials absent from HTML and browser POST data, protected auth-cookie attributes, refresh retention and explicit sign-out. Isolated tests cover environment, host/origin/project/account restrictions and denial before reading credentials. TypeScript and scoped lint passed. No new user was created and no AI request was made.

Run `npm run test:dev-login` for the dedicated browser check. Its configuration uses port 3106 and never writes authentication traces or stored session files.
