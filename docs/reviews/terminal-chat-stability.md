# Terminal and connected chat stability audit

20 October 2026. Requested investigation of the running website and terminal after repeated chat/session disruptions.

## Observed

Both local servers answered sign-in requests. The development log contained hundreds of repeated browser Suspense/server-render interruption errors interleaved with successful auth.identity and account.profile operations. This is distinct from the earlier identity-service outage page. A wallet extension also logged an inpage transport timeout; the extension warning is not an application session error. A clean browser could initially reproduce repeated sign-in navigations, then sign-in and chat behaved normally after the development server reloaded its current configuration. The historical log alone cannot establish the exact framework/stream cancellation that started each render interruption.

The code audit found three actionable reliability issues: post-login account reads treated service failure as a missing adult declaration and called signOut; navigation was immediately followed by refresh of the current route; successful metadata polls could repeatedly retry the same stale server render at the normal poll cadence.

## Changes

Account actions now request strict unavailable handling. A transient identity/profile failure after successful login returns an unavailable result without signing out or pretending the adult declaration was absent. Actual missing eligibility still denies access. Other account mutations also preserve the difference between a failed service read and a signed-out session.

Normal and explicit development sign-in navigate once to the returned destination, without a simultaneous refresh of the old route. The normal form wraps post-await navigation in a new transition. Server-action cookie writes already invalidate the authentication-dependent router cache.

Conversation sync backs off repeated attempts to render an unacknowledged revision: 5, 10, 20 and then 30 seconds. Metadata reads continue, an actually committed revision clears the delay, and a genuinely new remote revision can be rendered promptly. Only a rendered snapshot acknowledges catch-up. Slow in-flight refreshes are still protected; no message is replayed or generated by sync.

## Verification

Injected account-action tests passed for transient post-login failure without sign-out, genuine adult denial, invalid credentials and denied writes. Reply/identity/memory boundary checks passed. All 11 browser continuity/sync tests passed, including the new stale-render backoff case, draft retention, slow render protection, initial failure privacy, recovery without duplicated writes and expired-session sign-in. TypeScript and ESLint passed.

A read-only live browser check used the existing synthetic test account, blocked conversation POSTs, opened an existing chat, wrote only an unsent diagnostic draft, and simulated one changed sync revision. The page refreshed its RSC data without a document navigation, retained the draft, and emitted no browser error. The current development log was then checked and contained zero errors. No real messages were sent and no paid model calls were triggered. Private test credentials and storage-state files remain only in ignored local service storage.

This audit fixes the identified application reliability issues and verifies current operation. It does not claim every potential website bug is eliminated or that external services and browser extensions cannot fail.
