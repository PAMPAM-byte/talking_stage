# Reply save recovery · 20 October 2026

The founder reported an interrupted reply after “how are you?”. Read-only inspection showed the provider had returned successfully in roughly 2.6 seconds, followed by an approximately eight-second completion failure. The reply job remained generating with an expired lease, no failure code and no output message. The client correctly showed the expired-job interruption state; the character was not deliberately delaying a response.

The reply pipeline previously attempted completion once. It now retries only an idempotent completion RPC after a transient transport/service failure, with the same job, lease and generated output. It makes at most two save attempts separated by 150 ms, within the existing request deadlines and database lease policy. It does not claim another job, call the provider again or change budgets. Permission denials, permanent SQL/schema errors, discarded contexts and completed/failed business results do not retry. The shared path covers ordinary, photo, reaction and monetary-request replies. Existing completion guards still control eligibility, cancellation, generation and duplicate suppression. A second failed save remains unavailable; this is bounded recovery, not a guarantee against a prolonged outage.

Fixed-label ai.commit telemetry now distinguishes completion outcomes from provider outcomes without recording IDs, content, credentials or raw errors. A failed telemetry sink cannot interrupt persistence.

An authenticated recovery of the existing message exposed an additional context_limit error before the provider was called. The expanded media/reaction guidance plus the full published private character direction exceeded the configured 48,000-byte conservative input bound. Earlier semantic tests mostly used short public biographies, missing this full-direction interaction. Media output choices now use a compact ID/format/caption catalogue; complete incoming-media meanings still reach the model. Reaction guidance uses ordinary emoji examples rather than duplicating all 352 picker entries. Redundant prose in three conversation-style paragraphs was condensed while retaining personality, factual uncertainty, boundaries, memory, language, consent and identity rules. Limits, complete published directions and safety reserve remain unchanged. The failing real context measured about 44.7 KB after compaction.

New budget checks use all 50 complete published directions for greeting and wave turns with reaction metadata, an approved photo and payment eligibility: 100 cases must fit the actual 48,000-byte bound. Save tests simulate requests dropped before committing and acknowledgements lost after committing against the disposable PostgreSQL implementation; both preserve exactly one output and one provider call. Additional checks cover transient exhaustion, permanent error exclusion, unchanged payloads, all three completion RPC routes and telemetry isolation.

The existing user message was recovered through the normal authenticated, ownership-checked, budget-checked endpoint within its existing three-attempt policy. It completed successfully with no additional user message. This was recovery of the founder's pending conversation, not a synthetic live model evaluation. Provider credentials and private conversation content were not exported to this report.
