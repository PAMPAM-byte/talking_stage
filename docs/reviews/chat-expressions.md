# Chat expressions

The user requested WhatsApp-style emoji, sticker and GIF messages that characters can interpret. The connected composer now has a quiet smile icon opening a searchable, keyboard-accessible picker with Emoji, Stickers and GIFs. It follows the existing Manrope, rose, white and deep-red chat design. Emoji insert at the cursor, including into existing text. Eight original stickers and eight actual animated GIFs can be previewed, removed and sent alone or with a caption. Native keyboard emoji also remain supported.

Media uses a versioned, catalogue-only text envelope (`[[ts:sticker:wave]]` or `[[ts:gif:wave]]`, followed by an optional caption). This deliberately reuses the existing atomic save, ownership, client-message idempotency, reply jobs, clear/reset and privacy mechanisms without changing database grants or enabling arbitrary attachments. Captions reserve space within the existing 2,000-character message limit. Unknown or malformed envelopes render as ordinary text and cannot select a remote URL. Saved and optimistic messages use the same renderer; the Messages list shows a readable media preview. Older clients degrade to text rather than losing messages.

Before model delivery, user-media envelopes are expanded to catalogue descriptions and captions in the existing untrusted user-message context. Ordinary text and all Unicode emoji remain unchanged. Shared voice guidance asks characters to interpret reactions through the surrounding conversation, respond briefly, avoid unnecessary explanations and treat neither hearts nor hugs as consent to escalation or payment. Individual voices, adult access, visible AI disclosure, provider safeguards and memory rules remain in force. This adds no extra model call and does not grant visual access to arbitrary files.

All artwork is original, generated from checked-in vector source by `node scripts/build-chat-reactions.mjs`. GIFs play twice and stop within five seconds; reduced-motion users receive the SVG poster. Fixed dimensions avoid layout movement. Media stays on the application origin, without external search traffic, API keys or chat data sent to a GIF service. This initial release is a small built-in collection, not an external GIF search engine or upload feature.

Validation: all twenty offline core suites passed, including expression encoding/decoding, malformed and unknown tokens, actual GIF metadata, bounded animation, provider descriptions, captions and unchanged emoji. Existing eleven chat-delivery browser cases passed. Three new browser cases passed at 390px and 1440px, covering cursor insertion, search/empty states, Enter not sending from search, caption and media-only sends, removal, dismissal, failed-delivery idempotency, reduced motion and horizontal overflow. TypeScript and scoped lint passed. Screenshots are stored in the ignored `.local-services/chat-expressions-*.png` files. No paid live-model evaluation was made; semantic prompt delivery is verified, not a guarantee of every model interpretation.

The development preview now reads request search parameters inside Suspense, as required by the installed Next.js version. The floating development-tools badge is disabled so it cannot cover chat controls on localhost; compilation errors still surface normally and production has no such badge.

## GIF expansion and character reactions - 20 October

The current pack has 26 stickers, 20 GIFs and 352 emojis. Twelve original Naija illustrations now have eight-frame gesture animations, including funny, affectionate and goodnight reactions. Captions remain still for readability. The licensed Nollywood photographs remain sticker-only; these new GIFs are original illustrated reactions, not movie footage. Each GIF runs two short loops (2.24 seconds total), has a static SVG alternative under reduced motion, and is served locally.

All characters share a provider-side reaction catalogue and optional reply guidance. Existing user reaction descriptions and captions still reach the model in user-role context; plain Unicode emojis are preserved. The catalogue also lets the model interpret its own earlier reaction markers. Character replies can select one approved sticker/GIF with an optional caption, or use ordinary emoji text. Guidance favors ordinary text most of the time, individual personality, contextual interpretation and no repeated or automatically mirrored reactions. It preserves language preferences, substantive answers, distress handling, identity honesty and verified payment rules. No extra model request is added.

The shared provider boundary validates exact catalogue markers and rejects unknown, malformed, embedded or multiple reaction markers. A response accidentally combining a reaction with a photo or payment attachment keeps its caption (or reaction label) as text so the authoritative attachment still renders. Existing text-message persistence, ownership checks, reply leases and atomic commits remain in use; there is no new database schema, remote media URL or executable model action.

Validation: expression tests exercise every supported sticker/GIF through the provider output validator, semantic input delivery across all 50 public character profiles, malformed-output rejection, caption preservation, actual changing animation frames and an injected-provider reply commit. Existing provider and Anthropic transport checks and reply database integration pass. Four browser tests cover mobile/desktop sending, the expanded GIF list, character-side GIF/sticker rendering, captions, retry preservation and static reduced-motion posters. TypeScript and scoped ESLint pass. Visual review used the synthetic character-reaction preview. No paid live-model evaluation was performed; prompt delivery and media handling are verified, not a guarantee of every future model interpretation or choice.

## Natural media replies - 20 October

The founder reported a copied waving sticker accompanied by awkward entrance commentary. The renderer treats this as the character's own sticker plus caption; there is no quoted-message relation or swipe-reply action behind it. The greeting classifier previously received the expanded visual description, so a wave bypassed the short-greeting reminder. Adanna's established theatrical voice could then over-influence a minimal opening.

Cadence classification now uses the original user message independently of the model-facing visual descriptions and reaction metadata. Opening wave stickers/GIFs, Unicode waves with skin tones, and simple greeting captions receive the same short-greeting direction as written hellos. Final per-turn media guidance follows persona examples, favoring a plain text greeting over a copied wave, welcome speech, invented entrance or decorative laughing emoji. Captioned questions and serious messages retain their meaning. Waves later in a conversation can be farewells or acknowledgements and do not force a new introduction. General style guidance keeps humour grounded in actual conversation instead of making each personality trait a performance requirement. Media remains available when it contributes a fitting reaction; no output is replaced with a canned greeting and no extra model request is added.

Tests cover the exact opening-wave input through buildInput with reaction metadata, all 50 public profiles, greeting captions, skin tones, caption questions/distress/explicit media requests, ongoing goodbyes, unknown media, and preservation of identity honesty. Intent, provider, expression and message-reaction integration checks pass. These checks verify the runtime prompt path rather than the quality of a paid live-model sample; spontaneous wording remains model-generated. Existing saved messages are unchanged, and the updated instructions apply to new replies.

Subsequent full-direction testing found that the expanded guidance could exceed the input bound despite passing checks with short public biographies. The output catalogue and repeated style prose were compacted; incoming reaction meanings remain intact. Full private-direction budget regression checks now cover all 50 characters, including reaction and payment context. See [reply save recovery and prompt-budget diagnosis](./reply-save-recovery.md).
