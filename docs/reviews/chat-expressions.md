# Chat expressions

The user requested WhatsApp-style emoji, sticker and GIF messages that characters can interpret. The connected composer now has a quiet smile icon opening a searchable, keyboard-accessible picker with Emoji, Stickers and GIFs. It follows the existing Manrope, rose, white and deep-red chat design. Emoji insert at the cursor, including into existing text. Eight original stickers and eight actual animated GIFs can be previewed, removed and sent alone or with a caption. Native keyboard emoji also remain supported.

Media uses a versioned, catalogue-only text envelope (`[[ts:sticker:wave]]` or `[[ts:gif:wave]]`, followed by an optional caption). This deliberately reuses the existing atomic save, ownership, client-message idempotency, reply jobs, clear/reset and privacy mechanisms without changing database grants or enabling arbitrary attachments. Captions reserve space within the existing 2,000-character message limit. Unknown or malformed envelopes render as ordinary text and cannot select a remote URL. Saved and optimistic messages use the same renderer; the Messages list shows a readable media preview. Older clients degrade to text rather than losing messages.

Before model delivery, user-media envelopes are expanded to catalogue descriptions and captions in the existing untrusted user-message context. Ordinary text and all Unicode emoji remain unchanged. Shared voice guidance asks characters to interpret reactions through the surrounding conversation, respond briefly, avoid unnecessary explanations and treat neither hearts nor hugs as consent to escalation or payment. Individual voices, adult access, visible AI disclosure, provider safeguards and memory rules remain in force. This adds no extra model call and does not grant visual access to arbitrary files.

All artwork is original, generated from checked-in vector source by `node scripts/build-chat-reactions.mjs`. GIFs play twice and stop within five seconds; reduced-motion users receive the SVG poster. Fixed dimensions avoid layout movement. Media stays on the application origin, without external search traffic, API keys or chat data sent to a GIF service. This initial release is a small built-in collection, not an external GIF search engine or upload feature.

Validation: all twenty offline core suites passed, including expression encoding/decoding, malformed and unknown tokens, actual GIF metadata, bounded animation, provider descriptions, captions and unchanged emoji. Existing eleven chat-delivery browser cases passed. Three new browser cases passed at 390px and 1440px, covering cursor insertion, search/empty states, Enter not sending from search, caption and media-only sends, removal, dismissal, failed-delivery idempotency, reduced motion and horizontal overflow. TypeScript and scoped lint passed. Screenshots are stored in the ignored `.local-services/chat-expressions-*.png` files. No paid live-model evaluation was made; semantic prompt delivery is verified, not a guarantee of every model interpretation.

The development preview now reads request search parameters inside Suspense, as required by the installed Next.js version. The floating development-tools badge is disabled so it cannot cover chat controls on localhost; compilation errors still surface normally and production has no such badge.
